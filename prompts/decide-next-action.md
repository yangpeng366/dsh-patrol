# 下一步动作决策（一个 item → 固定三行输出）

本文件是提示词本体，一屏读完。它只回答「这一行的下一步具体做什么、要不要人拍板」，
不回答「这一行该不该跑」——后者是 Policy / Gate 的纯代码判定，不在这里投票。

## 输入（把这一段填好，整段贴给任何 LLM）

字段名与 `schemas/item.schema.json` 的 item 契约一致；没有值就留空，但保留行名，
免得模型把「空」读成「没这一项」：

```text
id: <源行唯一标识>
title: <人可读标题>
repoPath: <本地仓库路径；无仓留空>
description: <这一行要做什么>
nextStep: <方向表「下一步」原文>
priority: <P0 ｜ P1 ｜ P2>
intervalMin: <分钟；0 表示停跑>
threadId: <续跑会话 id，可空>
fake: <true ｜ false，是否只做 dry-run>
lastRun: <ISO 时间，上一轮何时跑过>
currentStage: <当前阶段>
achievement: <上一轮已落地的产出；没有写「无」>
actionType: <「动作类型」列原文；空表示没填>
```

## 输出（只回这三行，不要标题、解释、代码块、前后缀）

```text
动作: <本轮唯一要做的一件事，一句祈使句>
理由: <不超过 30 字>
人工介入: 是 ｜ 否
```

本轮若形成可复用做法，追加一行（没有就省略）：

```text
沉淀: - <做法> — <命令>
```

`是 ｜ 否` 是二选一，不要两个都写，也不要写「看情况」。

## 判定规则

- 信息够、动作可逆（读文件、写本地文件、跑离线测试）→ `人工介入: 否`。
- 有外部副作用（发布、git push、改生产、花钱、发消息）或缺关键输入，或 `nextStep` 与
  `currentStage` / `achievement` 互相矛盾 → `人工介入: 是`，并在动作里写清要人定哪一条。
- `intervalMin` 为 0 或空 → 动作写 `待人工确认`，`人工介入: 是`，理由写「该行已停跑」。
  停跑的行不替它找活干。
- `fake: true` → 只给可逆的读或试运行动作，不给写操作。
- `actionType` 非空时，动作必须落在该类型允许的范围内；为空时不要替人补一个类型。
  「动作类型」的取值以 `src/core/action-vocabulary.ts` 的词表为准——本提示词不复制词表，
  也不把词表读成「建议」。
- `repoPath` 为空、或 `lastRun` 之后仓库状态未知 → 先给「确认仓库位置 / 跑一次只读探测」，
  不要直接改仓。
- 不确定就走不确定：动作写 `待人工确认`，`人工介入: 是`，理由写缺哪条信息。禁止编一个动作凑数。
- 输入为空、看不懂或与巡检无关 → 动作 `无法判断`，`人工介入: 是`。

## 边界

- 解析器只核格式（三行齐不齐、值空不空、`人工介入` 是不是 是/否），不判断动作是否合理、
  理由是否成立，也不核对 `actionType` 与动作是否一致。格式契约与错误码见
  `docs/decision-prompt.md`。
- 三行之外的任何行都当杂音：不影响解析，只被记进 `ignoredLines`。
